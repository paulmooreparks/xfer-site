# XFER0903

**Informational.** Symbol mapped to JSON string.

## What it means

A symbol became a JSON string, because JSON has no symbols. Reading the JSON back gives a string, not a symbol. This is informational and is reported once per conversion, with a count.

## An example

From the conformance suite, `to-json/813-symbols-and-temporals`:

```xfer
{ mode dark when 2025-08-01 at 09:30:00.250 stamp 2025-08-01T09:30:00Z local 2025-08-01T09:30:00 }
```

```
$ xfer to-json --json example.xfer
{"mode":"dark","when":"2025-08-01","at":"09:30:00.250","stamp":"2025-08-01T09:30:00Z","local":"2025-08-01T09:30:00"}
{"file":"example.xfer","code":"XFER0903","severity":"info","message":"symbol mapped to JSON string: 1 symbol, first at /mode","start":{"offset":0,"line":1,"column":1},"end":{"offset":0,"line":1,"column":1}}
{"file":"example.xfer","code":"XFER0904","severity":"info","message":"temporal mapped to JSON string: 4 temporals, first at /when","start":{"offset":0,"line":1,"column":1},"end":{"offset":0,"line":1,"column":1}}
```

## How to fix it

Nothing needs fixing. If the value should be a string in both formats, write it as a string in XferLang too.

## In the specification

Section 8.1, [XferLang to JSON](https://github.com/paulmooreparks/xferlang/blob/v1.0.0-draft.1/spec/xferlang.md#81-xferlang-to-json), of the specification at `v1.0.0-draft.1`.
