# XFER0101

**Error.** Scalar token not followed by a separator.

## What it means

A scalar token (a string, number, temporal, keyword or symbol) runs straight into the next token. Only whitespace, a comment, a bracket or the end of the document may follow a scalar, so the parser cannot tell where one ends and the next begins.

## An example

From the conformance suite, `invalid/101-second-point`:

```xfer
1.5.5
```

```
$ xfer validate example.xfer
example.xfer:1:4: error XFER0101: scalar token not followed by a separator: found "."; a fractional number needs a digit before the point
```

## How to fix it

Put a space between the two tokens. Look for a key and a string written together (`title"x"`), two strings (`"a""b"` is one string, but `"a"1` is two tokens), or a number with something attached to it (`1-2`, `10px`).

## In the specification

Section 4, [Lexical structure](/page/spec/lexical-structure), of the [specification](/page/spec) at `v1.0.0-draft.1`.
